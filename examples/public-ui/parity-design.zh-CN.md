# 九张公开 UI 画板的优化方案与技术评审

**评审结论：建议分批实施。** 首批交付桌面插件的可编辑单行文字修复，同时在采集器验证动画结束后的状态。第二批恢复组件实例关系，并用稳定弹窗校准背景模糊。历史画板逐张达到原像素门槛、组件和交互复验通过后，再作为通过案例展示。

## 从哪里开始

证据版本为 `655c39e`。九张画板的超差比例为 1.0076%–11.9448%，原门槛为每通道容差 16/255、每板超差像素占比 ≤1%。109 个被场景显式标记的组件出现位置，在 Figma 画板中保留了 47 个原生实例。四条已声明的点击路径完成了浏览器回放和 Figma 目标回读，Present 实际播放仍待验证。逐板数字见同目录 `results.json`。

| 评审发现 | 影响 | 设计决定 |
| --- | --- | --- |
| `Button` 在 Chromium 和 Figma 都是 Geist Regular 24 px、框宽 72.875 px。原画板把 `n` 排到了下一行 | 填对字体属性仍会出现断词。上轮探针只增加内部文本框宽度就恢复了单行 | 第一批修复直接使用原采集包和桌面插件，保留父框、热点与对齐锚点 |
| Cal.com 两个日期的 Figma 填充与采集包一致，却与参考截图不同。shadcn 采集还记录了入场过程中的透明度 | 改写 Figma 色值会把一次采集偏差带入以后的导入和反向补丁 | 新采集加入终态检查。报告保留旧输入缺失或矛盾的信息 |
| 62 个实例缺口中，61 个可由当前结构或样式比对重放解释 | 放松比对会误认组件，给每个外观新建主组件也会虚增复用率 | 以组件来源和显式状态组织变体，以关联到正确主组件的源节点数衡量复用 |

## 实施与验收

### 第一批 A · 修复单行文字，保护反向同步

1. 在桌面插件导入时，优先读取源文本、浏览器实际用字证据、字号、字重、字距、行高及对齐方向。按这些属性缓存 Figma 测量探针，记录实际加载字体与回退。对旧包中无法判定是否为单行的节点，保留原排版并标记待核对。多行正文、混排和省略号分别走对应的测试用例。
2. 对已确认的一行文字，先尝试原框并验证实际排出的行数。发生二次换行时，在相邻图层和祖先裁剪边界允许的范围内，寻找足够容纳整行的最小宽度。左对齐固定左边、右对齐固定右边、居中固定中心。组件外框和点击区域沿用源坐标。空间不足时，输出节点、实际字体和缺口，供定位替代字体或排版差异。
3. 复用 MCP 渲染器已有的测量与可用空间计算思路。桌面插件仍负责这批包含位图和原生输入框的画板。把源框、计划绘制框和从 Figma 回读的实际框分开记录。几何审计逐项验证补偿依据、锚点和边界，继续检查其他节点的源几何。
4. 以 `Button`、`Continue`、日期 `25` 作失败样本，日期 `24` 作原本正常的对照。再测一段正常换行的正文、一处窄容器和一个中英文混排标签。核对导出行数、文本完整性、相邻内容、基线及实际 `TEXT` 类型。升级渲染器后，同一采集包首次导入生成新版画板；在同一渲染版本再次导入应幂等。保留旧版本上的人工改动。

**评审修正。** 插件按输入摘要复用旧页面。若省略渲染策略版本，新代码有机会直接返回旧画板，导致验收根本没有运行新算法。将渲染版本纳入复用和增量更新条件。首次导入后立即导出，预期代码补丁为空；人工修改一个已支持回写的映射字段后，再核对三方补丁只命中该字段。渲染补偿只记录为导入元数据。

### 第一批 B · 采集相同的可见状态

在 `capture.mjs` 现有 `ready` 之后增加有界的稳定性检查。shadcn 关注弹窗、遮罩和受影响的背景，Cal.com 关注旧选中日、新选中日和时段面板。先确认场景语义成立，再等待相关有限动画结束。按“截图 A → 读取 DOM 的几何、样式和原生资源位置 → 截图 B”采样，两端同时校验相关节点的渲染属性与状态。严格验收要求两张全视口截图一致；原生输入位图从本轮通过的截图裁切。截取期间发生变化则整轮重试，超时列出变化区域。这个协议给出可观测的稳定性证据，仍无法证明任意网页的 DOM 与合成器可以原子读取。

**验收。** 冻结弹窗与日期选择夹具分别连续采集三次，检验透明度、边界、选中语义和纯色内部像素。增加“几何稳定但颜色仍在过渡”的反例，以及一个持续动画页面验证有界超时。减少动态效果偏好、固定延时或单个 `visible` 条件均不足以独立判定终态。

### 第二批 A · 恢复可复用组件

优先复用显式 Figma 库引用，再使用代码组件身份或场景声明的家族。为 Plane 的 `Continue Button` 声明启用与禁用，为 Cal.com 的 `Calendar Day` 声明可选、禁用、选中，状态来自组件属性或 DOM 语义。按钮文案使用文本属性，图标使用可见性或实例替换；稳定的尺寸和状态差异才成为命名变体。缺少来源或属性冲突时，导出可编辑图层并记录具体原因。对缺少状态信息的历史包只使用可证明的匹配，将推断单列。

**验收。** 为历史 109 个源节点逐一登记源 ID、实例 ID、主组件或组件集、变体及退化原因，另查此前未解释的 1 个缺口。Plane 两态必须可定位到同一家族的正确变体。对日历增添一个只有文案不同的日期，主组件数量应保持稳定；修改主组件的共享样式应传播到实例，各实例保留自己的日期。验证交换两个结构相似但来源不同的组件会触发审计失败。外部组件库映射失败后创建的本地主组件单独记账。

### 第二批 B · 复刻弹窗背景模糊

先覆盖已经观察到的 `backdrop-filter: blur(...)`。采集遮罩几何、填充与透明度、背景模糊半径、裁剪和前后层级；能识别的原生 `::backdrop` 与页面自建遮罩分别定位。桌面插件将背景模糊放在背景之上、弹窗内容之下。用明暗硬边和背景文字夹具，测定 CSS 与 Figma 两种模糊半径的实际对应关系。

**验收。** 在终态锁定的同一夹具里做四次导出，分别组合开启或关闭模糊、半透明或不透明弹窗。单独对照背景边缘、弹窗正文和整板，人工查看原图、Figma 导出及热图。背景发生模糊时，前景文字仍应清楚且可编辑。旧采集包缺失滤镜参数时，报告说明缺失来源；有可追溯的冻结源码可用于独立实验。

## 发布评审

| 验收对象 | 证据与判定 |
| --- | --- |
| 历史九板 | 现有 `verify-evidence.mjs` 应继续精确重放旧失败。另用核对过的原采集包、新桌面插件和新 Figma 独立节点导出，对比原 Chromium PNG。记录参考图 RGBA 摘要、输入包摘要、渲染器版本、每板修复前后数值和热图。每一板独立应用 1% 门槛 |
| 新采集 | 新参考图与新包成对保存，报告标明环境、场景、采集时间及终态证据。公开网站内容变化时，记录该轮输入。历史包与旧图已经矛盾的区域，可以在历史报告中保持未通过，同时在新报告中验证根因修复 |
| 组件与交互 | 独立记录组件身份、主组件传播、文本可编辑性、位图区域和各项退化。重新执行四条浏览器点击，回读触发节点和目标，并在 Figma Present 实际点击打开、关闭弹窗，以及选择日期、时段。Plane 范围止于填写邮箱 |
| 兼容与反向同步 | 旧 v1 包照常读取，新增采集证据为可选字段。运行现有单元及集成测试，对已通过的原有夹具复验。验证零人工编辑产生零补丁，双端同时修改同一字段仍报告冲突 |

**实施决策。** 先核对输入包摘要与九张参考图的对应关系，再并行开展第一批 A、B。文字修复可以立刻以旧输入测量收益；采集修复可以立刻在冻结页面证明能否重复得到同一状态。完成两项后按残余热图排序。相同 HEX 对应多个语义 token 时保留映射歧义，待能核对 CSS 变量来源再绑定。扩大色域支持、跨平台统一字体或重构整套渲染器，均缺少本批优先投入的证据。
